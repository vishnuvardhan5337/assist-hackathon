{\Large\bfseries Design note: the work assistant that remembers}\\[1pt]
{\color{muted}\small BuildSprint Round 3 \quad·\quad

\vspace{4pt}
\textbf{Principle: code decides, the model only reads language.} Who may see what, which value is newest,
what has expired and what was forgotten are all decided by plain, testable Python. A small model (Groq,
\code{gpt-oss-120b}, free tier) is used only where code cannot read the language: nicknames (``the London
account''), open questions (``When is my Dubai trip?'') and feedback in unusual wording. Every line cites
record ids, and code checks them before printing. On days 1--5 most outputs use \textbf{0 tokens}.

{\small\color{muted}\code{ingest} $\rightarrow$ store records + yesterday's feedback $\rightarrow$ model fallback (checked)
\quad|\quad \code{brief}/\code{ask} $\rightarrow$ \textbf{privacy gate} $\rightarrow$ facts $\rightarrow$ person's memory
$\rightarrow$ answer with sources}

\section{1. How do we pick the records for a brief, and what goes in it?}
\begin{enumerate}
  \item \textbf{Privacy gate first.} \code{World.visible(person)} keeps only the person's company, team records,
        their own private notes and restricted records that list them, minus anything forgotten. Nothing else is read.
  \item \textbf{Meetings} are events whose start falls on the date in the person's own time zone. The window is
        everything since their last meeting with that client, by date (a later meeting the same day has not happened yet).
  \item \textbf{Changed}, most important first: client facts that changed (launch date, billing owner; old and new
        record both cited) $\cdot$ decisions in notes $\cdot$ blocked tasks $\cdot$ tasks done, re-dated, re-owned
        or cancelled (net change per task) $\cdot$ deliveries.
  \item \textbf{Promises} are matched by grammar, not sentences (Hinglish ``\emph{kal tak bhej dunga}'', ``by EOD'',
        ``by next Monday''). Due dates use the author's time zone. A promise stays open until delivered or its task is done.
  \item \textbf{Model fallback} (once a day, at ingest): only messages that look like an ownership change, a date move or a
        promise but match no rule. A model fact is kept only if its quote is really in that record, the person exists and
        the date parses; a person \emph{handing over} work is rejected as the new owner. Invented quotes are rejected (tested).
  \item \textbf{The person's memory}: max $N$ changes, blockers first, skipped and ``ignored'' topics, forgotten things.
        Nothing left means \code{nothing\_new} with empty lists. We never write filler.
\end{enumerate}

\section{2. How do we save memory, and who may see it?}
One SQLite file: raw records, feedback (read one day late, as required), forget requests, checked model facts and a model
cache. Facts are \textbf{rebuilt from visible records on every call}, never kept in a shared summary, so what one person may
not see can never shape another's output, and a \emph{forget} applies everywhere at once. Preferences and ignored topics
belong only to the person who gave them; corrections fix a team fact only within the corrector's own company.

\section{3. How do we know which information is newest?}
Each client fact keeps a timeline of claims, resolved by four rules: \textbf{(1)} the newest claim wins; \textbf{(2)} an
intern cannot overrule anyone, and a question is never a claim; \textbf{(3)} a new document version counts only for fields it
actually changes, so a stale copy still saying ``Billing: Kavya'' changes nothing; \textbf{(4)} a correction from the person
we brief beats older claims, but not genuinely newer news. Task state comes from real status, owner and due changes, never
comments. Leave expires after its end date, judged by the asker's own date and time zone.

\section{How we checked for overfitting}
The rules were written after reading days 1--5, so we reworded those days (same records, ids and official keys) and scored
them with the organisers' scorer. Set A was used while fixing; set B was written \emph{before} any fix and scored once,
blind: \textbf{64.0/85}. Privacy and honesty stayed at 1.00 throughout, so unfamiliar wording caused misses, never leaks or
invented facts. Only general fixes followed: answers lead with the asked-for fact plus owner, due date and status; promise
grammar; a client-fact fallback; number words; looser corrections; the checked model fallback.

\section{4. What will we not do?}
\begin{itemize}
  \item Obey text inside a record: record text reaches the model only inside \code{<record>} tags marked as untrusted data.
  \item Cite or hint at another company's record, someone else's private note, or a restricted record not addressed to the
        asker. When the answer exists only there, we refuse.
  \item Print a line without a supporting source. If unsure, we leave it out.
  \item Send a whole day to the model: prompts stay at 1.5--3.5k tokens, under the 8k and 4k limits.
  \item Hardcode names, nicknames, ids or answers from days 1--5, or let the model decide privacy, recency or forgetting.
\end{itemize}
